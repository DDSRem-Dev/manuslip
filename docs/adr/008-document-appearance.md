# Document appearance

Status: accepted on the Windows baseline for ADR002 item23; Windows package acceptance is recorded in VALIDATION.md, iteration99.

Document actions → Document appearance offers offline font families, text size, line spacing and writing width. Changes apply immediately; Close returns to writing and Reset defaults removes every override. Default values preserve each surface's existing defaults. Typography applies to Source, Live Preview, reading and export. A local stylesheet applies to Live Preview, reading and export; Source provides a usable fallback. Scoped CSS leaves the editor mounted and creates no source history event. Changes synchronize pending input, refresh measurement and preserve source, every selection and undo history. They do not request translations or change translation cache keys.

The importer accepts an explicitly selected regular UTF-8 `.css` file, at most64KiB. PostCSS8.5.31, already installed and now an exact desktop runtime dependency, parses a limited content-style language. Rules select Markdown tags using descendant or child combinators; `body`, `:root` and `.markdown-body` are root aliases. Headings and inline formatting also map to their Live Preview classes. Every branch receives a main-owned document scope. Arbitrary classes, attributes, pseudo selectors, sibling selectors, nesting, at-rules, URLs, escapes, custom properties and `!important` are rejected. Unsupported files retain the previous stylesheet.

Supported declarations include local font families, bounded font size/weight/style/leading, colors, text alignment/decoration/transform, nonnegative margin/padding, border longhands, table details and list style. Use `border-width`, `border-style` and `border-color` rather than the border shorthand. Font sizes are clamped to10–64px; spacing is bounded to64px or4em/rem, border width to4px, letter spacing to−2–8px, and unitless leading to1–3. Color functions are allowlisted. Imports permit at most128 rules,256 selectors,1,024 declarations,512 units per selector and1,024 units per value. Compiled CSS is limited to128KiB. No font download, background fetch or file watcher is introduced.

Application controls, dialogs, Save, Reset and Source remain outside document CSS. Trusted controls embedded in Live widgets explicitly restore application typography and colors. A valid stylesheet can deliberately make document text unreadable; the dialog, Reset and Source still work.

Main owns the native picker, validates the sender frame and document UUID, derives named-path keys, and rechecks path, owner and operation generation after asynchronous work. A renderer cannot supply an arbitrary file path or global CSS. One CSS picker per owner remains charged until it settles. Reset, a path change, document closure or frame replacement invalidates an older import. Preload validates both request and response contracts.

Untitled appearance stays in its session. First save persists it under the canonical path hash. Save As inherits appearance for the new path and retains the old entry. The profile repository contains at most128 entries and9MiB of validated data; capacity never silently evicts another document. Serialized atomic writes update repository memory only after success. Invalid data receives a recovery backup. Future schemas retain the original plus a backup and open read-only. A failed write leaves session appearance, Reset, Source and Retry save usable. Closing a document/window releases its binding and invalidates pending work.

HTML/PDF export captures safe typography and compiled CSS once before the destination picker. Later appearance changes cannot alter that job. HTML embeds the captured CSS; the existing isolated print surface applies it before layout and asset measurement. Export CSP, diagram/print preloads, document/source bounds, parser patches and semantic resource gates are unchanged.

Acceptance covers hostile CSS and bounds, corrupt/future profiles, serialized write failure, ownership and stale-picker races, unchanged source/history/selections, actual computed containment, first save/Save As, restart, unreadable-content recovery, styled reading export, translation request reuse, English/light and Chinese/dark interfaces, narrow layouts and accessibility. The Windows package and full regression evidence is retained under `test/artifacts/logs/`; other-platform acceptance remains separate.

The compiler also supplies internal heading color/weight variables so CodeMirror token highlighting inherits explicit content styles. User-defined custom properties remain rejected; Source retains its original token defaults. Native tests check the visible heading token in both themes.
